# Contributing to Pitwall

Thanks for helping. Bug reports, playtest notes, new scenarios, radio lines and code are all welcome.

## Report a bug

Open an issue with:
- your browser and version, and your device (laptop model or GPU);
- what the setup panel said about the voices ("rendered on this device's GPU", or the CPU-mode note);
- the race (scenario, full race or season round), and what you did and saw;
- anything from the browser console, if you can.

## Run it locally

You need Node.js 22.18+ (or 24+) and npm.

```sh
npm install
npm run dev      # the first run saves the AI models (about 1.5 GB) to models/; PITWALL_SKIP_MODELS=1 skips this
npm test         # simulation, conversation, parser, radio and voice tests
npm run build    # strict TypeScript check and the static bundle
```

## How the project is put together

- `src/sim.ts`: the deterministic race simulation. One tick is one second, and randomness comes from the seed only (`raceRandom`), so a seed and its calls always replay the same race.
- `src/scenarios.ts`, `src/roster.ts`, `src/season.ts`: circuits, the 15 scenarios, the fictional grid and the season.
- `src/intent.ts`: turns what the player says or types into a call or a question.
- `src/conversation.ts`: the team's radio, scripted from race events.
- `src/brain*.ts`: the optional team chat model. It only talks, never changes the race.
- `src/radio*.ts`, `src/sound.ts`: voices, the radio queue and procedural sound.
- `src/circuit-paths.ts`: generated by `scripts/build-circuit-paths.mjs`; don't edit it by hand.

## Ground rules

- Every change to the race goes through `applyCommand`. The AI model never issues race calls.
- Keep the simulation deterministic: no `Math.random` or wall-clock time in `src/sim.ts`.
- New scenarios should be tuned so that doing nothing misses at least one goal and a specific call meets both. The tests check this for each scenario.
- Radio lines stay in character: Theo is calm and dry, Nico is quick and impatient, James decides, Maya is technical, Eli is all numbers.
- Record design decisions, and the measurements behind them, in `DECISIONS.md`.
- Run `npm test` and `npm run build` before you open a pull request.
- Keep teams and drivers fictional, and don't add official logos or broadcast audio.
